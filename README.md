# UFML Minecraft Java 启动器

一个零第三方依赖的 Minecraft Java 版启动器，使用 Java 17+ 和 Swing 编写。界面、日志和错误信息均为中文。

## 菜单与功能

启动器把下载、管理和启动拆成三个独立菜单，可下载版本与本地已下载版本不会混在同一列表：

- **下载游戏**：只列出尚未安装的远程版本。选择版本后点击“安装此版本”，会先弹出独立安装窗口；确认加载器与其他安装选项后才开始下载客户端、运行库、资源索引、资源对象和原生库，并准备匹配的 Java。
- **游戏管理**：只列出已经下载到本地的版本，可按正式版、快照版、远古版、愚人节版分类查看。每个版本行右侧都有独立的“设置”入口。
- **启动游戏**：只扫描并读取本地实例，使用本地文件与本地 Java 启动，不会为了启动而联网补文件。

下载页和游戏管理页都以完整的版本菜单为主体；正式版、快照版、远古版和愚人节版会分开显示，愚人节版本不会混入普通快照。

点击“安装此版本”后打开的安装窗口会显示游戏版本、版本类型、发布时间、下载来源和目标实例目录，并提供加载器选择。还可以决定安装完成后是否将新实例设为当前启动版本、是否自动进入启动游戏页。取消窗口不会下载或修改任何文件。

界面采用无边框透明玻璃窗口：桌面可透出，顶部空白区域可拖动窗口，右上角提供最小化和关闭按钮。主窗口支持拖动任意边缘或四角调整大小；版本设置子窗口保持相同风格，并可拖动标题区域移动。

## 版本设置

在“游戏管理”中选择本地版本，点击版本栏旁的“设置”即可管理该实例。设置只作用于当前版本：

- 指定该版本使用的 Java，留空则跟随全局设置或自动检测。
- 设置该版本的内存上限，留空则跟随全局内存设置。
- 设置全屏、游戏窗口宽度与高度。
- 添加额外的 JVM 参数和游戏参数。
- 设为当前启动版本、打开该版本目录、补全游戏文件或删除本地版本。

“补全游戏文件”是手动触发的联网操作。它会读取本地版本元数据，按 SHA-1 和文件大小检查客户端、运行库、资源、原生库等文件，只重新下载缺失或校验失败的内容，并准备该版本所需的 Java。补全失败不会影响其他版本；普通启动仍严格使用本地文件。

删除版本时只删除该版本的目录和独立设置，公共运行库与资源会保留。

## 模组加载器

安装时可以选择：

- **原版**：只安装 Mojang 官方游戏文件。
- **Fabric**：从 Fabric Meta 获取稳定的 Loader 配置，并下载其运行库。
- **Fabric + API**：安装 Fabric Loader，并从 Modrinth 获取适配当前 Minecraft 版本的 Fabric API，放入实例的 `mods` 目录。
- **Forge**：下载官方 Forge 安装器，使用其 `--installClient` 流程生成本地 Forge 实例。

Fabric 和 Forge 实例的 `inheritsFrom` 继承配置会递归合并客户端、主类、运行库、JVM/游戏参数、资源索引和 Java 版本要求，不会把合并后的配置写回原始版本 JSON。

Forge 安装需要可用的 Java，且官方安装器受网络和 Forge 发布状态影响，可能需要较长时间。

## 本地与离线行为

- 本地版本直接通过 `versions/*/*.json` 扫描，不需要远程版本清单即可显示。
- 版本清单和版本元数据下载后会缓存到 `Config\cache`，下载页下次可优先使用缓存。
- 下载与手动补全会校验文件大小和 SHA-1；启动页只按本地文件判断，绝不会静默联网补文件。
- Java 运行时只在安装或手动补全阶段准备；启动页只使用系统已有 Java 或已下载的本地运行时。

## 运行

环境要求：JDK/JRE 17 或更高版本。

```powershell
.\build.ps1
.\start.bat
```

也可以直接运行已构建的 JAR：

```powershell
java -jar .\build\UFML-Launcher.jar
```

运行全部测试：

```powershell
.\test.ps1
```

生成自带 Java 运行时的 Windows EXE：

```powershell
.\package.ps1
```

输出：

- 可直接运行的 EXE：`UFML\UFML-Launcher.exe`
- 游戏实例、运行库与资源：`UFML\Minecraft`
- 启动器配置、缓存、运行时与日志：`UFML\Config`
- 分发压缩包：`build\UFML-Launcher-Windows-x64.zip`

绿色版目录中的 `runtime` 已包含 Java，目标电脑无需另装 Java。`UFML-Launcher.exe` 必须和同级的 `app`、`runtime` 目录一起分发，不能只复制单个 EXE。

测试覆盖版本继承与 Maven 运行库、Forge 版本选择、版本独立设置、本地版本扫描，以及“首次联网安装后完全离线启动”。测试还验证了同大小损坏文件可在补全时重新下载，而普通启动不会发起 HTTP 请求。

## 数据位置

| 内容 | 固定位置 |
| --- | --- |
| 启动器配置 | `UFML\Config\config.json` |
| 日志 | `UFML\Config\logs\launcher.log` |
| 版本清单与版本元数据缓存 | `UFML\Config\cache` |
| 自动下载的 Java 运行时 | `UFML\Config\runtimes` |
| 各版本独立设置 | `UFML\Config\version-settings.json` |
| 游戏实例、客户端、运行库、资源与原生库 | `UFML\Minecraft` |

游戏目录固定为启动器旁的 `Minecraft` 文件夹，不再允许在界面中切换。版本、运行库、资源和原生库都保存在这里；启动器配置、Java 运行时、缓存和日志统一放在同级的 `Config` 文件夹。

## 当前限制

- 仅支持离线账户，不支持 Microsoft 登录；不能加入开启正版验证的服务器。
- 目前使用 Mojang、Fabric、Forge 与 Modrinth 的官方接口，没有 BMCLAPI 等镜像切换。
- 已提供 Fabric API 自动安装，但还没有独立的模组浏览、安装和冲突管理界面。
- Forge 安装依赖官方安装器，不同 Minecraft 版本和网络环境下的耗时、失败原因可能不同。
